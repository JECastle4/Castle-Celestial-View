## Phase 2-4 Implementation Plan: Performance Optimization & Scaling

**Status**: Phase 1 ✅ Complete (Cyclomatic complexity F→A). Phase 2-4 starting.

### Phase 2: Computational Optimization + Caching (v1.1.0)

#### 2.1 Batch Astropy Call Optimization
- **File**: `api/services/batch_earth_observations.py`
- **Issue**: `_fetch_all_celestial_bodies()` calls astropy ~18 times per frame individually
- **Solution**: Vectorize to batch all frames at once
- **Benefit**: 5-10x speedup for frame_count=1000
- **Target**: <10 sec response time

#### 2.2 Eclipse Detection Workflow Optimization
- **Files**: `api/services/astronomical_events.py`, `api/services/eclipse_detection.py`
- **Issue**: Linear search (7,200 samples for 10-year range) + expensive shadow geometry
- **Solution**: Adaptive sampling near eclipse nodes, cache expensive minimizer
- **Benefit**: 2-3x speedup for 10-year eclipse searches
- **Target**: <5 sec response time

#### 2.3 Request-Level Response Caching
- **File**: `api/routes.py`
- **Issue**: Identical requests recompute all results
- **Solution**: LRU cache with 1-hour TTL
- **Benefit**: ~30-40% request hit rate, ~5-10MB memory per 100 cached responses

#### 2.4 Performance Profiling & Baseline
- **File**: `scripts/performance-profiling/benchmark.py` (new/enhanced)
- **Issue**: No performance tracking
- **Solution**: CLI tool to measure CPU, memory, astropy call count before/after
